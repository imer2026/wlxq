# 英雄变身（变身术）支持 —— 设计文档

日期：2026-09-13
状态：待用户评审
前置事实：[游戏规则知识库](../../game-rules.md)（变身为本设计新增的游戏规则段落，见 §2）

## 1. 背景与目标

游戏新增英雄能力「变身术」：点击棋盘上的英雄后，其头顶悬浮变身按钮，点击按钮、等待动画后，该英雄变成本局携带 4 种英雄中**除自身外其他 3 种**之一，**星级不变**。每局有 2 次变身机会，允许对同一位置连续使用。

自动化用途（用户策略 2026-09-13）：3 星非主 C 英雄出现且尚未达标主 C 时，用变身碰主 C（每次 1/3 概率，连用两次 5/9）。变身免费，优先于召唤/合成执行。

- 合作与保卫宠物两种模式都启用（对局界面同款）。
- 默认开启，配置可关；模板缺失时自动禁用（WARNING 日志），不影响其他流程。

## 3. 方案比选（已定：方案 A）

- **方案 A：培养循环内的决策分支 + 动作序列（采用）**。变身是 `BUILD_MAIN_C` 里与合成拖动同构的短动作（点格 → 点按钮 → 等待 → 验证），完成后回到同一决策循环；不新增状态机 State。连用第二次不需要额外机制——变身成功后回到决策循环，`select_transform` 重新评估，同一位置的英雄若仍是 3 星非主 C 自然再次入选。
- 方案 B：独立 `State.TRANSFORM` + 状态迁移 + 界面门控表条目。变身没有独有的页面形态（仍在对局界面）、没有跨状态要维护的中间进度，新增状态只增加迁移和门控维护面。否决。

## 4. 架构设计

### 4.1 决策层（`tasks/strategy.py`）

`CultivationStrategy` 新增纯决策方法：

```python
def select_transform(
    self, board: BoardSnapshot, used_count: int, max_count: int
) -> BoardHero | None:
```

同时满足以下条件时返回变身目标（多个候选按棋盘位置顺序取第一个），否则返回 `None`：

1. 尚无达标主 C（复用 `has_target_main_c`，即无 `hero_type = 主C && star_level >= target_star_level`）；
2. `used_count < max_count`（本局次数未用完）；
3. 棋盘存在 `star_level >= transform_min_star_level`（默认 3）且非主 C 的英雄。

星级下限放 `run` 配置（默认 3）是仓库「阈值不入代码」约定；用户已定案仅 3 星触发，调整该值属将来独立决策。纯决策、只依赖快照与配置，可直接单测。

### 4.2 执行层（`tasks/coop.py`，`BUILD_MAIN_C` 决策点）

变身检查插在棋盘识别后的决策优先级**次前**——击杀奖励弹窗的优先关闭逻辑保持最前不变，其后就是变身，再往后才是批次召唤/批次合成/单动作合成/召唤。命中变身条件时优先执行，免费且可能直接达标。

动作序列（单次变身）：

```text
点击目标英雄格中心（复用格子坐标模型 cell_center，不新增坐标）
→ 轮询匹配按钮：每 transform_button_poll_interval_seconds（默认 0.3 秒）截一帧
   在动态搜索窗口内匹配，至多等 transform_button_appear_timeout_seconds（默认 1.5 秒）
   （实测按钮约 1 秒内弹出；轮询不发送输入）
→ 未出现：重点击英雄一次（首次点击可能未落在英雄上）后再轮询，
   重点击预算 transform_button_reclick_max（默认 2）
   ——重点击只发生在按钮确实未弹出的情形；按钮已弹出时不重复点击英雄，
   避免被游戏当作「点击其他位置」而关掉按钮
→ 轮询超时仍无按钮：视为游戏侧无变身次数（如程序重启后内存计数失步），
   放弃本次、回常规决策，不结束任务（计数失步自愈兜底）
→ 命中：点击按钮中心（match_center）
→ 等 0.3 秒复查按钮已消失（按钮先消失、英雄才开始变身，实机确认）；
   按钮仍在 = 点击未落在按钮上，在重点击预算内重点按钮
→ 按钮确认消失（变身已开始）：扣减本局变身计数
→ 等待 transform_settle_seconds（默认 4.0 秒，实测动画稳定时长）
→ 动作后验证：重新识别棋盘，该位置英雄「类型改变且星级不变」才算成功
   （变身类型必变，类型未变 = 变身未生效或动画未完）
→ 验证失败：在 transform_verify_attempts（默认 2）预算内再等 settle 后重识别；
   仍失败记 WARNING、放弃本次，回常规决策，不结束任务
```

验证成功后回到决策循环顶部：重新识别已是常规节奏，`select_transform` 用最新快照重新评估——变出主 C 则 `main_c_ready` 正常触发停止培养；仍是 3 星非主 C 且还有次数则对同一位置再次变身（用户定案连用）；次数用完回常规召唤/合成流程。变身后英雄若与棋盘上其他英雄构成同型同星对，由现有合成决策自然处理，无特殊逻辑。

每次变身扣减计数器的时机是**按钮确认消失后**（变身已实际开始，开环计次不再回看棋盘验证结果，与技能刷新「点击发送即计为已用」同一哲学）；棋盘验证失败不返还次数（变身已开始，结果只是识别问题），最坏只损失识别置信，不影响对局。

计数器 `_transform_used_count` 的重置点与 `_skill_refresh_used_count` 完全一致（点准备进局 / 被踢重进 / 结算重开）。程序中途重启丢失内存计数、本局重新获得机会，与技能刷新同属已知边界。

### 4.3 按钮搜索窗口（格子几何推导，非全局 ROI）

按钮位置随被点英雄所在格线性推导（§2 实测），搜索窗口按格子中心动态计算，比例参数进 `configs/tasks.yaml`：

```text
窗口 x ∈ [格子中心 x ± horizontal_span]（horizontal_span ≈ 1.0 格宽，覆盖水平偏差）
窗口 y ∈ [格子中心 y - upward_span, 格子中心 y + downward_span]
        （upward_span = 2.0 格高：实测按钮中心在格中心上方约 1.05 格高、按钮顶边
         上探到约 1.7 格高，2.0 含两侧余量且覆盖第 1 排越出棋盘顶边的情形；
         downward_span ≈ 0.2 格高：按钮底边略压本格顶边、侵入本格约 0.4 格高）
```

该窗口对任意排（含第 1 排——窗口向上越过棋盘顶边进入中间过道带）机械成立；模板匹配复用现有原语，ROI 矩形由任务层按格子几何换算后传入，不新增全局固定 ROI。

### 4.4 配置

`configs/default.yaml` `run` 段新增：

```yaml
transform_enabled: true          # 总开关；false 或模板缺失时禁用
transform_max_per_round: 2       # 每局变身次数上限
transform_min_star_level: 3      # 触发变身的最低星级（仅该星级及以上的非主C触发）
transform_button_poll_interval_seconds: 0.3   # 点英雄后轮询按钮的截帧间隔
transform_button_appear_timeout_seconds: 1.5  # 按钮弹出等待上限（实测约 1 秒内弹出）
transform_button_reclick_max: 2      # 按钮未弹出时重点击英雄 / 按钮未消失时重点按钮的预算
transform_settle_seconds: 4.0        # 点按钮后等变身动画稳定（实测约 4 秒）
transform_verify_attempts: 2         # 动作后验证（含再等待重识别）的轮数
```

`configs/tasks.yaml` 新增：

```yaml
locators:
  transform_button:               # buttons/bian_shen.png，阈值 0.85（实机命中 0.984+，余量充足）
                                   # action_point: match_center；无固定 ROI，窗口按格子几何动态传入
transform_button_search:          # 搜索窗口比例参数（相对格子中心，跨度以格宽/格高为单位）
  horizontal_span: 1.0            # 单侧水平跨度，单位：格宽
  upward_span: 2.0                # 向上跨度，单位：格高（按钮中心约在上方 1.05 格高，
                                   # 顶边至 1.7 格高，见 §4.3 几何推导）
  downward_span: 0.2              # 向下跨度，单位：格高
```

模板 `assets/templates/3000x2000/buttons/bian_shen.png` 已入库；其余分辨率模板包照旧为空，沿用现有模板包选择策略。

### 4.5 保守失败路径

- 模板文件缺失：启动时不报错，变身功能降级禁用并打 WARNING（变身是增益能力，缺素材不应阻断整局 run）。
- 按钮未弹出（轮询超时）：大概率游戏侧次数已尽（如程序重启后内存计数失步），放弃本次自然兜底，不误重试。
- 按钮点击落空（按钮未消失）：重点击按钮预算内重试；耗尽记 WARNING 跳过。
- 棋盘验证失败（类型未变）：验证预算内再等待重识别；耗尽记 WARNING 放弃本次，回常规决策。
- 窗口失效（格子几何参数缺失）：跳过变身，回常规决策。
- 第 1 排按钮渲染未实测：失败路径天然兜底（找不到按钮 → 重点击 → 放弃），记 TODO 待实机观察确认。
- 对局结束信号（返回按钮）优先级高于变身动作，沿用现有门控。

## 5. 测试计划

1. **纯决策单测**（`select_transform`）：无达标主 C + 3 星非主 C 存在 → 返回目标；有达标主 C → `None`；次数耗尽 → `None`；多候选按位置序取第一个；2 星非主 C 不触发（`transform_min_star_level=3`）；4 星非主 C 触发（`>= 3`）。
2. **Fake 输入执行序列测试**（沿用 `test_coop_task.py` 的 fake Vision/Action 模式）：点格 → 按钮命中 → 点按钮 → 按钮消失确认后扣计数；按钮未弹出 → 轮询超时 → 重点击英雄预算 → 放弃回常规决策（计数失步自愈）；按钮未消失 → 重点按钮预算；验证类型未变 → 放弃跳过回常规决策；验证成功后决策循环回访（连用第二次 / 变出主 C 停培养）；计数器与技能刷新同点重置。
3. **离线模板回归**（一次性，非 CI）：5 张实机截图断言按钮命中且中心落在几何窗口内（截图不入库，验证脚本与结论记录在设计文档/TODO）。
